# Bug repair ledger

- 2026-09-15: the first concurrent queue stopped at `OpenBMI_MI/fold3/seed2` with `DefaultCPUAllocator: not enough memory`. The runner retained both the normalized NumPy signal arrays and their identical CUDA tensors for train, validation, and outer-development splits. The signal arrays are now removed from the data dictionary immediately after the unchanged contiguous tensor transfer. Dataset values, ordering, model computation, optimization, checkpoint selection, and metrics are unchanged. Existing cell checkpoints remain resumable.
- 2026-09-15: the first resume exposed a device-compatibility bug in RNG restoration because `map_location=cuda` moved saved ByteTensor RNG states to CUDA while PyTorch requires CPU RNG-state tensors. Restoration now explicitly returns those state tensors to CPU before calling the unchanged RNG APIs. No random state is regenerated or altered.
- 2026-09-15: resume deserialization now occurs on CPU. PyTorch transfers live model and optimizer state to the existing parameter device, while historical checkpoint copies and the selected best state remain on CPU. This removes redundant CUDA residency during resumed cells without changing any tensor value or optimizer state.
