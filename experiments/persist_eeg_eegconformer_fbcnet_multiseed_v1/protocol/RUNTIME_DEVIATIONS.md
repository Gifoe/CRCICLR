# Runtime deviations

None at protocol lock. The 128-sample batch is fixed. If a particular cell cannot fit, any batch/accumulation adjustment must be recorded here before that cell is retried; no architecture change is permitted.

Fixed FBCNet filter-bank outputs are stored as fold-local runtime memmaps to avoid repeatedly filtering the same training trials. This is numerically the same deterministic `float32` transform and is excluded from the repository. Resume snapshots capture the optimizer, RNG, selected state and epoch, so an interrupted cell resumes without redoing completed epochs.

After the first ten cells, the single 32 GB RTX 5090 used under 4 GB VRAM during FBCNet training, while the 32-logical-core host showed about 5% total CPU and under 1% disk busy in a sample. The queue was therefore partitioned into two disjoint **model shards**, one EEG Conformer and one FBCNet, each with its own Windows scheduled task and log. The training function, ordered batches, per-cell seeds, data splits, loss, optimizer, early stopping and checkpoint selection remain identical. No model/task/fold/seed cell is assigned to both shards, and only the FBCNet shard writes fixed-filter scratch. Checkpoint/resume identity is unchanged. This is a scheduling change, not a scientific-protocol change; observed throughput and memory are monitored for contention.

After EEG Conformer completed all 60 cells, FBCNet was still processing OpenBMI ERP. A third scheduled task was assigned only the 15 FBCNet OpenBMI SSVEP cells, with a separate task-shard log and the existing per-cell checkpoint/resume paths. The original FBCNet queue remains on ERP; when it reaches SSVEP it will verify and skip completed cells. The task-specific filter scratch directories are distinct. No training or evaluation rule was changed. This scheduling adjustment is valid only while the SSVEP shard finishes before the original queue reaches SSVEP; if it does not, the original queue must be held at the task boundary to prevent duplicate writes.

The SSVEP shard exited successfully after all 15 cells. With the original FBCNet queue entering ERP fold 3, a new disjoint shard was assigned only the 15 WBCIC MI cells. It uses the same task-filtering mechanism and separate WBCIC scratch directory. The original queue is expected to verify and skip these completed cells after ERP; if the WBCIC shard has not completed by then, the original queue must be held at the task boundary to avoid duplicate writes. No scientific parameter or checkpoint-selection rule changed.
